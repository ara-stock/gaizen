# gaizen.xyz 再設計（2026-09-20）

## 1. 結論

- サイトの主役を **「仮想通貨プロジェクト トラッカー」** に移す。ブログは「株式」と「仮想通貨」の2本柱に絞り、トラッカーへ人を運ぶ補助役にする。
- 収益の主軸は **AdSense ではなくリファラル（紹介リンク）**。AdSense は「通ればおまけ」の位置づけに下げ、承認のための作業はやめる。
- 更新の最小単位を「記事1本（数時間）」から **「JSON 1行の更新（数分）」** に変える。今の関心（仮想通貨プロダクト）と日々の行動がそのままサイト更新になる構造にする。

## 2. なぜ AdSense が通らないのか（現状診断）

リポジトリから確認できる事実：

| 事実 | 影響 |
|---|---|
| 47記事のうち44本が 2026-05-16〜06-20 の5週間に公開。05-28 は1日で10本 | 短期間の大量公開は、審査で「有用性の低いコンテンツ」と判定されやすい典型パターン |
| 47本中31本が `us-stock` カテゴリで、題材は S&P500・NISA・オルカン・高配当ETF など | 大手証券会社・大手メディアと正面衝突する題材。金融は YMYL（お金や生活に影響する分野）で、匿名の個人サイトは審査が最も厳しい |
| 全記事に英語版がある（計94ページ） | 読者のいない英語版が、サイト全体の「薄いページ」の比率を押し上げている |
| 直近コミット7件がすべて「AdSense readiness」系の改修 | デザインや構造の問題ではなく、コンテンツの性質の問題。これ以上の体裁改修は効果が見込めない |

加えて、今後の主題である仮想通貨（特にエアドロップ・海外DEX・紹介リンク）は、AdSense と相性が悪い。承認されても広告単価は低く、紹介リンクの多いページは審査で不利に働く。

**判断：AdSense 承認を目標にするのをやめる。** 月1万PVで数千円規模の収益のために、書きたくない記事を書き続ける構造が一番のリスク。

## 3. 新しいサイト構成

```
gaizen.xyz
├── /tracker/            ★主役。プロジェクト一覧（フィルタ・並び替え・ステータス管理）
│   └── /tracker/[slug]/  プロジェクト別ページ（検索流入の受け皿・紹介リンク設置場所）
├── /blog/               株式（企業分析・保有方針） + 仮想通貨（実録）
├── /portfolio/          現状維持
├── /tools/              現状維持（FIRE試算など）
└── /referral/           トラッカーに役割を吸収。将来的にトラッカーへ 301
```

### トラッカーの項目

| 項目 | 種別 | 内容 |
|---|---|---|
| ステータス | 筆者の状況 | 取組中 / 様子見 / TGE済・受領 / 撤退。**訪問者は自分用に変更でき、ブラウザに保存される** |
| TGE | 事実 | 上場済みなら日付とティッカー。未上場なら見込み時期と情報源の種別（公式 / 報道 / 噂 / 未発表） |
| ポイント期待値 | 主観 5段階 | 根拠コメントを必ず添える |
| チーム信頼度 | 主観 5段階 | 根拠コメントを必ず添える |
| VC調達額 | 事実 | 開示済み総額（百万ドル）、ラウンド、主な投資家 |
| 拠点・トップ | 事実 | 国（会社所在地 / 創業者の拠点を区別）、創業者名、匿名かどうか |
| リスク | 事実 | ハッキング、規制、日本からの利用制限、KYC など |
| 出典 | 事実 | 全プロジェクトに一次情報または主要メディアのURL |

事実と主観を分けているのは、信頼性のためであると同時に、「調達額は調べれば誰でも分かるが、実際に触った人の評価は他にない」という差別化のため。

### データの持ち方

- `content/projects/projects.json` の1ファイル。型は `types/project.ts`。
- 追加・更新は Claude Code に「Xを追加して」「edgeX を TGE済に」と頼めば済む。出典URLは必須。
- 静的サイトのままなのでサーバー費用は増えない。

## 4. マネタイズ設計

優先順位順。

### ① リファラル（主軸・すでに開始可能）

- トラッカーの各行とプロジェクト別ページに「始める」ボタンを設置済み。既存の紹介コード（edgeX / GRVT / Jupiter / Nado / xStocks / Huma など）をそのまま使う。
- Perp DEX の紹介報酬は「紹介した人が払う取引手数料の一定割合」が継続的に入る形が多く、1人の活発なトレーダーが AdSense 数万PV分に相当しうる。料率は各プログラムで異なり変更も多いので、プロジェクトごとに公式ページで確認して `statusNote` に書く。
- 導線：X の投稿 →（プロジェクト別ページ）→ 紹介リンク。検索流入は「{プロジェクト名} TGE いつ」「{プロジェクト名} エアドロ」「{プロジェクト名} 調達額」を狙う。プロジェクト別ページの title はこの形にしてある。

### ② X との連動（集客の主軸）

- 週1回「今週のトラッカー更新」（ステータス変更・TGE情報の変化）を投稿する。ネタはトラッカーの差分そのもの。
- 既存の `/tools/x-copy` を、トラッカーの差分から投稿文を作る方向に拡張できる（次フェーズ）。

### ③ 実録記事（ブログの仮想通貨側）

- 他の誰にも書けない題材がすでにある：**edgeX × Hyperliquid × Lighter × Extended の funding carry bot を実際に運用している記録**。月次の損益、ポイント獲得量、事故と対策。
- これは AGENTS.md の方針（一次情報・筆者の実体験）と完全に一致し、紹介リンクとの相性も良い。月1本で十分。

### ④ 将来の選択肢（アクセスが付いてから）

- 有料 note / メンバーシップ（月次の詳細レポート、bot の設定値）。
- プロジェクトからのスポンサー掲載（必ず「PR」表記。評価とは切り離す）。
- AdSense の再申請（株式の企業分析記事が積み上がった後。通らなくても計画に影響なし）。

## 5. 先に確認が必要なリスク

1. **日本の規制。** 日本で登録のない暗号資産交換業者への勧誘・媒介は資金決済法上の問題になりうる。DEX の紹介リンクの扱いは明確でない部分があり、金融庁の方針次第で変わる。断定はできないので、(a) トラッカーには免責と「金融庁未登録」の明記を入れた、(b) 「必ず儲かる」等の表現は使わない、(c) 収益が大きくなる前に一度専門家に確認する、を推奨する。
2. **景品表示法（ステマ規制）。** 紹介リンクには広告である旨の表示が必要。ボタン直下と一覧ページ下部に明記済み。
3. **評価の独立性。** 紹介報酬のあるプロジェクトだけ高評価にすると、トラッカーの価値が消える。紹介コードのないプロジェクトも載せ、低評価・撤退も公開する。
4. **既存の誤記。** `/referral/` で edgeX を「Solanaベース」と説明しているが、誤りの可能性が高い。トラッカー側は出典つきで記載し直した。

## 6. ブログ側の整理（提案・未実施）

既存記事には手を入れていない。以下は承認をもらってから行う。

- 英語版記事：新規作成をやめる（AGENTS.md の「バイリンガル記事」ルールの見直し）。既存は残すか noindex にするか要判断。
- 汎用記事（S&P500 vs オルカン、NISA入門系など）：筆者の実体験が薄いものは統合または noindex。
- 残す柱：企業分析（Alphabet、MUFG、総合商社、銀行株）、保有方針、資産管理Excel、仮想通貨の実録。
- トップページ：トラッカーを最上部に出す（現在のトップは未コミットの改修中のため、今回は触っていない）。
